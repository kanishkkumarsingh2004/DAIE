# Orchestrator vs Parliament

While both **Orchestrator** and **Parliament** are multi-agent coordination structures within the Decentralized AI Ecosystem (DAIE), they serve entirely different purposes and rely on distinct architectural flows. 

Understanding when to use which is critical for building effective multi-agent systems.

## At a Glance

| Feature | Orchestrator | Parliament |
|---------|--------------|------------|
| **Core Paradigm** | Hierarchical Task Execution | Peer-to-Peer Deliberation ("Mixture-of-Agents") |
| **Primary Goal** | Breaking down and executing multi-step workflows | Maximizing accuracy and drastically reducing hallucinations |
| **Input Routing** | Main Agent analyzes prompt → creates distinct sub-prompts | Identical user prompt is routed to all agents simultaneously |
| **Team Structure** | Main Agent (Coordinator) + Sub-Agents (Workers) | Equal Peers (Specialists) + 1 Speaker (Synthesizer) |
| **Execution Flow** | Dynamic (Main Agent decides who does what, and when) | Strictly Staged: 1. Generate → 2. Peer Review → 3. Synthesize |
| **Agent Interactions**| Top-down delegation via explicitly defined A2A logic tools | Horizontal cross-peer review (Agents critique rival answers) |
| **Output Assembly** | Main Agent merges distinct pieces together to form the answer | Speaker fuses all data and critiques into a unified consensus |
| **Prompt Injection** | Adds hierarchical team mechanics (e.g., context rules, roles) | Retains pure domain specialization (e.g., Economist, Lawyer) |
| **Latency Profile** | Variable (depends entirely on how the Main Agent delegates) | Higher (requires waiting on full generation and review rounds) |
| **Token Consumption** | Moderate (Agents only process their assigned sub-task payload) | Heavy (All agents must deeply read all other agents' initial responses) |
| **Ideal Use Cases** | Automated labs, procedural pipelines, structured simulations | Complex fact-checking, ethical/legal deliberation, analytical consensus |

---

## The Orchestrator: Hierarchical Task Execution

The `Orchestrator` uses a top-down, hierarchical approach. It functions like a manager delegating discrete tasks to specialized team members.

### How it Works:
1. **User Input:** Sent directly to the Main Agent.
2. **Decomposition:** The Main Agent analyzes the request and breaks it down into distinct sub-tasks.
3. **Delegation:** The Main Agent uses tools to assign those sub-tasks to specialized Sub-Agents (e.g., assigning data collection to a "Researcher" and translation to a "Translator").
4. **Aggregation:** The Main Agent receives the disparate results back, combines them, and creates a unified final output.

**Best For:**
- Tasks requiring multiple distinct skill sets.
- Scenarios with defined sequential steps (e.g., Research -> Analyze -> Report).
- Top-down simulations (e.g., a "Professor" managing a "Research Lab" or a "Judge" presiding over a "Courtroom").

---

## The Parliament: Deliberative Consensus

The `Parliament` uses a horizontal, decentralized approach often referred to as "Mixture-of-Agents." It acts like a panel of experts attempting to solve a single complex problem cooperatively.

### How it Works:
1. **Initial Answer (Parallel):** All sub-agents receive the *exact same* prompt and generate their own independent answers based on their specific domain instructions.
2. **Cross-Peer Review:** Every agent receives the answers generated by all *other* agents in the parliament. They critique each other's work constructively, looking for flaws or factual inaccuracies.
3. **Synthesis:** A designated "Speaker" agent takes the original prompt, all initial answers, and all peer reviews to synthesize a single, highly accurate consensus output.

**Best For:**
- Complex, analytical reasoning questions where accuracy is paramount.
- Drastically reducing AI hallucinations.
- Problems that benefit from cross-examination by diverse perspectives (e.g., a Lawyer, an Economist, and an Ethicist all debating the same topic to find the best conclusion).

---

## The Bottom Line

- Use an **Orchestrator** when you need a team to **divide and conquer** (doing different things and combining them).
- Use a **Parliament** when you need a team of experts to **peer-review and converge** (looking at the same thing to find the singular most accurate truth).
