# Parliament Architecture

The **Parliament** architecture in DAIE brings true "Mixture-of-Agents" peer-review into the decentralized swarm, creating an incredibly rich deliberation process that dramatically improves output quality and prevents hallucinations.

Whereas a standard `Orchestrator` merely aggregates information or delegates linear tasks to specialized agents, the `Parliament` treats sub-agents as equals attempting to find the most accurate analytical answer.
## Architectural Flow

```text
┌──────────────────────────────────────────────┐
│                  USER PROMPT                 │
└──────────────────────┬───────────────────────┘
                       │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
   ┌────────────┐┌────────────┐┌────────────┐
   │  AGENT A   ││  AGENT B   ││  AGENT C   │
   │  (Answer)  ││  (Answer)  ││  (Answer)  │
   └──────┬─────┘└──────┬─────┘└──────┬─────┘
          │             │             │
          └─────────────┼─────────────┘
                        ▼
             ┌─────────────────────┐
             │  CROSS-PEER REVIEW  │
             │  • A reviews B & C  │
             │  • B reviews A & C  │
             │  • C reviews A & B  │
             └──────────┬──────────┘
                        │
                        ▼
             ┌─────────────────────┐
             │  SPEAKER (Synthesis)│
             │  (Selects Best Data)│
             └──────────┬──────────┘
                        │
                        ▼
┌──────────────────────────────────────────────┐
│           CONSENSUS OUTPUT TO USER           │
└──────────────────────────────────────────────┘
```

## How It Works

The Parliament deliberation loop follows three core steps:

1. **Initial Answer (Parallel)**: All sub-agents receive the exact same prompt and utilize their domain-specific instructions to formulate a response independently.
2. **Peer Review**: Every agent reviews the answers generated by all *other* agents in the parliament. They analyze strengths, weaknesses, and factual inaccuracies constructively. Agents do not review themselves.
3. **Synthesis**: A designated "Speaker" agent takes the original prompt, all initial answers, and all peer reviews to synthesize a single authoritative answer, smoothing out contradictions and removing hallucinated claims that didn't survive review.

## Configuration Options

The Parliament constructor accepts several parameters to customize behavior:

- `sub_agents`: List of DAIE Agents to form the parliament (minimum 2 for peer review)
- `speaker`: Optional Agent to act as the synthesizer (defaults to first sub_agent)
- `max_review_rounds`: Number of review rounds before synthesis (default: 1)
- `config`: Additional configuration parameters including:
  - `agreement_threshold`: Similarity threshold for early stopping (default: 0.85)
- `max_concurrency`: Concurrency limit for local execution (default: 8)
- `distributed`: If True, uses CommunicationManager to DELIVER tasks to remote nodes
- `communication_manager`: The CommunicationManager to use for distributed tasks
- `distributed_timeout`: Seconds to wait for remote responses (default: 30)

## Structured Output Formats

Parliament uses Pydantic models for structured LLM outputs:

### ReviewOutput
Each agent's peer review contains:
- `strengths`: Strengths of the previous answers
- `weaknesses`: Weaknesses and flaws of the previous answers  
- `suggested_improvements`: Actionable improvements to fix flaws
- `confidence`: Confidence weight of this review block from 0.0 to 1.0

### ConsensusOutput
The final synthesis contains:
- `final_answer`: The finalized, synthesized, fully complete answer
- `consensus_confidence`: Aggregate holistic confidence metric from 0.0 to 100.0 (percentage)
- `reasoning`: Brief reasoning on how consensus was reached and contradictions were resolved

## Advanced Features Already Implemented

### Multi-Round Review
The `max_review_rounds` parameter allows configuring multiple review rounds where agents can iteratively refine their assessments based on peer feedback.

### Early Stopping Consensus
Parliament automatically calculates agreement between reviews using TF-IDF cosine similarity. If the agreement exceeds the `agreement_threshold` (default 85%), deliberation stops early to save computation.

### Distributed Execution
Setting `distributed=True` enables Parliament to operate across network nodes using a CommunicationManager, allowing geographically dispersed agents to participate in deliberations.

### Dynamic Agent Selection
The `deliberate_with_router()` method uses the DAIE AgentRouter to dynamically select the most relevant agents from a larger pool for each deliberation topic.

### Error Handling
Graceful degradation when agents fail - failed responses are replaced with placeholder text and deliberation continues with available agents.

## Pros and Cons Analysis

### Advantages of Parliament Architecture

| Pros | Explanation |
|------|-------------|
| **Reduced Hallucination** | Cross-agent review significantly minimizes fabricated or inaccurate information |
| **Improved Accuracy** | Diverse domain expertise leads to more comprehensive and precise answers |
| **Bias Mitigation** | Multiple perspectives counterbalance individual agent biases |
| **Enhanced Explainability** | Structured review process provides clear audit trail for decisions |
| **Complex Problem Handling** | Excels at multifaceted issues requiring interdisciplinary knowledge |
| **Robustness to Failure** | System continues functioning even if individual agents fail |
| **Specialization Utilization** | Leverages domain-specific agent training effectively |
| **Iterative Refinement** | Multiple review rounds allow progressive improvement of answers |
| **Efficiency Optimization** | Early stopping prevents unnecessary computation when consensus reached |
| **Scalable Distribution** | Supports geographically dispersed agent collaboration |
| **Dynamic Relevance** | AgentRouter selects most pertinent experts for each query |
| **Structured Output** | Standardized JSON format enables downstream processing integration |

### Disadvantages and Challenges

| Cons | Explanation |
|------|-------------|
| **Increased Computational Cost** | Multiple agents and review rounds consume more resources |
| **Extended Response Latency** | Deliberation process takes longer than single-agent responses |
| **Conflicting Expert Opinions** | Irreconcilable differences between agents may hinder consensus |
| **Implementation Complexity** | More intricate to develop and maintain than simpler architectures |
| **Agent Quality Dependency** | Overall performance limited by weakest participating agent |
| **Synthesis Difficulties** | Resolving profound contradictions between expert views challenging |
| **Network Latency Issues** | Distributed setups suffer from communication delays |
| **Optimal Sizing Challenges** | Determining ideal agent count for specific domains non-trivial |
| **Groupthink Risk** | Homogenous agents may reinforce rather than challenge biases |
| **Coordination Overhead** | Managing inter-agent communication consumes significant resources |
| **Confidence Calibration** | Difficulty ensuring confidence scores accurately reflect certainty |
| **Debugging Complexity** | Tracing errors across multiple interacting agents intricate |

## Usage

```python
from daie import Agent, AgentConfig, AgentRole
from daie.agents import Parliament
from daie.chat import ParliamentChatConfig

# 1. Define specialized agents
agents = [
    Agent(config=AgentConfig(name="Economist", role=AgentRole.DATA_ANALYST)),
    Agent(config=AgentConfig(name="Lawyer", role=AgentRole.SECURITY_AUDITOR)),
    Agent(config=AgentConfig(name="Ethicist", role=AgentRole.GENERAL_PURPOSE))
]

# 2. Assemble the Parliament with advanced configuration
parliament = Parliament(
    sub_agents=agents, 
    speaker=agents[0],
    max_review_rounds=3,  # Multiple review rounds
    config={"agreement_threshold": 0.9},  # Higher consensus threshold
    max_concurrency=4
)

# 3. Deliberate Using Interactive Chat Loop
config = ParliamentChatConfig(parliament=parliament)
config.run()
```

### Programmatic Usage (Non-Interactive)
```python
# For programmatic access without interactive chat
result = await parliament.deliberate("Your question here")
print(result["final_answer"])
print(f"Confidence: {result['consensus_confidence']}%")
```
